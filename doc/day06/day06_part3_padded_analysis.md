# Day 6 第三部分：Padding 消除 Shared-memory Bank Conflict

> 归档位置：`doc/day06/`；原始数据见同目录 `day06_transpose.csv`。

## 1. 实验目的

普通 tiled 转置已经把全局显存访问优化为：

```text
连续读取 input
→ shared memory 中转置
→ 连续写入 output
```

但 `tile[32][32]` 在按列读取 shared memory 时，同一个 warp 的不同地址会映射
到同一个 bank。

本实验通过增加一列 padding：

```cpp
float tile[32][33];
```

验证以下假设：

> 改变 shared-memory 每行的物理跨度，可以消除转置读取时的 bank conflict，
> 从而在不改变数学计算和全局显存数据量的前提下提高性能。

## 2. 实验控制变量

三个版本使用相同的：

- 输入数据；
- CPU reference；
- 矩阵尺寸；
- `32 × 8` 线程块；
- `32 × 32` 逻辑 tile；
- 20 次预热；
- 50 次正式测量；
- CUDA Event 计时；
- 中位数统计；
- 有效带宽公式；
- 正确性判断标准。

普通 tiled 与 padded 的核心差别只有：

```text
tiled： tile[32][32]
padded：tile[32][33]
```

第33列不存有效矩阵数据，只改变 shared-memory 行跨度。因此这是一个控制变量
较好的对照实验。

## 4. 指标解释与判断标准

### `kernel_ms_median`

50 次 Kernel 时间样本的中位数，单位为毫秒。

在相同矩阵尺寸和相同数学工作下：

```text
越低越好
```

### `GB_per_s`

每个元素按一次全局读取和一次全局写入计算：

```text
4 Byte + 4 Byte = 8 Byte/元素
```

所以：

```text
有效带宽
= elements × 8 Byte / Kernel 时间
```

在相同算法工作量下：

```text
越高越好
```

这是有效带宽，不是显存总线的真实流量。缓存流量、无效内存事务和
shared-memory 流量没有直接进入分子。

### `correct` 与误差

所有结果均为：

```text
correct = PASS
max_abs_error = 0
max_rel_error = 0
first_mismatch = none
```

转置只复制 `float`，不包含会产生舍入误差的算术，因此必须精确一致。

## 5. 正确性分析

Padded 版本在以下边界类型上全部正确：

- 极小非方阵 `3 × 5`；
- 非 tile 整数倍 `17 × 19`；
- 大型不规则非方阵 `1003 × 769`；
- 大型方阵 `2048 × 2048`；
- 更大方阵 `4096 × 4096`。

这说明增加的第33列只改变物理存储布局，没有改变：

- 输入坐标；
- 输出坐标；
- tile 的有效数据区域；
- 非方阵的行列交换；
- 边界线程的判断。

## 6. 大矩阵加速结果

| 规模 | Tiled → Padded | 相对 Tiled 时间降低 | Naive → Padded | 相对 Naive 时间降低 |
|---:|---:|---:|---:|---:|
| 1003 × 769 | 2.07× | 51.8% | 3.68× | 72.8% |
| 2048 × 2048 | 1.64× | 38.9% | 3.03× | 66.9% |
| 4096 × 4096 | 1.44× | 30.7% | 2.81× | 64.4% |

计算公式：

```text
加速比 = 优化前时间 / 优化后时间

时间降低比例
= (1 - 优化后时间 / 优化前时间) × 100%
```

三个大尺寸中，padded 全部显著快于 tiled，不属于只有一两个百分点、可能被
普通测量波动解释的差异。

## 7. 分规模分析

### `3 × 5`

三个版本都在约 4.2～4.4 微秒：

```text
naive  = 0.004192 ms
tiled  = 0.004368 ms
padded = 0.004352 ms
```

15 个元素的数据处理时间远小于 Kernel 启动、调度、同步和计时固定开销。
因此 `0.03 GB/s` 不能用于评价 padding，也不能认为 padded 与 naive 的显存
效率相同。

### `17 × 19`

Padded 的 `0.61 GB/s` 略高于另外两个版本，但总时间仍只有约 4 微秒。这个
差异很小，不能作为 padding 有效的主要证据。

这两个小尺寸的作用是验证正确性。

### `1003 × 769`

```text
tiled：  0.025808 ms，239.09 GB/s
padded： 0.012448 ms，495.70 GB/s
```

Padded 相对 tiled：

```text
加速 2.07×
时间降低 51.8%
```

即使矩阵尺寸不是 tile 整数倍，边缘 block 存在无效线程，padding 仍然获得
明显收益。

### `2048 × 2048`

```text
naive：  164.08 GB/s
tiled：  303.41 GB/s
padded： 496.37 GB/s
```

这是本次测得的最高有效带宽。

Padded 相对 tiled 加速 `1.64×`，相对 naive 加速 `3.03×`。这说明：

1. 合并全局写入解决了第一层瓶颈；
2. 消除 shared-memory bank conflict 又解决了第二层瓶颈；
3. 两层访存优化可以累积，而不是互相替代。

### `4096 × 4096`

```text
naive：  0.819200 ms，163.84 GB/s
tiled：  0.421056 ms，318.76 GB/s
padded： 0.291824 ms，459.93 GB/s
```

这是更能代表大工作集持续吞吐的尺寸。

Padded 相对 tiled：

```text
加速 1.44×
时间降低 30.7%
```

相对 naive：

```text
加速 2.81×
时间降低 64.4%
```

Padded 在这里仍有显著收益，但有效带宽低于 `2048 × 2048` 的
`496.37 GB/s`。

## 8. 为什么 padding 能产生这么大的提升

普通 tiled 声明：

```cpp
float tile[32][32];
```

对32位 word，简化的 bank 映射为：

```text
bank = (row × 32 + col) mod 32
     = col
```

转置读取时，同一 warp 访问：

```text
tile[0][固定列]
tile[1][固定列]
...
tile[31][固定列]
```

这些是不同地址，但全部映射到同一个 bank。

Padded 声明：

```cpp
float tile[32][33];
```

新的映射为：

```text
bank = (row × 33 + col) mod 32
     = (row + col) mod 32
```

同一列的32行现在依次落入32个 bank。额外一列只增加：

```text
32 × 4 Byte = 128 Byte/block
```

却消除了转置读取的严重冲突。

由于两个 Kernel 的逻辑 tile、线程配置、全局访问和数学结果相同，而性能差异
很大，本实验强烈支持：

> `tile[32][32]` 的 shared-memory 列读取确实是普通 tiled 版本的重要性能
> 瓶颈，`tile[32][33]` 成功改变了 bank 映射。

## 9. 与理论显存带宽的关系

RTX 2080 Ti 的参考理论显存带宽为 `616 GB/s`。

| 规模 | Padded 有效带宽 | 相对理论峰值 |
|---:|---:|---:|
| 1003 × 769 | 495.70 GB/s | 80.5% |
| 2048 × 2048 | 496.37 GB/s | 80.6% |
| 4096 × 4096 | 459.93 GB/s | 74.7% |

对一个还包含 shared-memory 搬运、同步、边界判断和地址计算的转置 Kernel，
这个结果已经较好。

但这些比例不能叫作精确的“DRAM 利用率”，因为：

- `616 GB/s` 是理论峰值；
- benchmark 计算的是算法有效带宽；
- 相同输入和输出缓冲区被重复执行50次；
- 较小工作集可能获得一定缓存复用；
- 没有 profiler 的 DRAM 字节数和 shared bank conflict 计数。

## 10. 为什么 `4096 × 4096` 低于 `2048 × 2048`

从 `2048 × 2048` 增大到 `4096 × 4096`：

```text
元素数量：增加4倍
时间：0.291824 / 0.067600 ≈ 4.32倍
带宽：496.37 → 459.93 GB/s
```

时间增长略高于理想的4倍，所以带宽下降约7.3%。

可能因素包括：

- 更大的工作集更依赖真实显存访问；
- 缓存和地址转换行为发生变化；
- GPU 时钟、温度和系统状态变化；
- 单次运行仍存在正常测量波动。

当前数据不足以区分这些原因。因此正确结论是：

> 最大尺寸仍保持约 `460 GB/s` 的高有效带宽，但出现了规模相关下降；需要
> 重复运行或 profiler 数据才能确定具体原因。

不能仅凭这三组时间断言是某一个缓存层或某一种硬件资源造成。

## 11. 能证明什么，不能证明什么

### 当前实验能强力支持

1. Padded 版本计算正确。
2. Padding 对三个大矩阵均有显著性能收益。
3. 普通 tiled 的 shared-memory 访问存在重要优化空间。
4. `32×33` 布局比 `32×32` 更适合本次转置列读取。
5. 只增加128 Byte shared memory，就换来了最高约 `2.07×` 的 tiled 后续
   加速。

### 当前实验不能单独证明

1. 每个 warp 精确产生了多少次 shared-memory 事务；
2. 所有性能提升都百分之百来自 bank conflict；
3. `496.37 GB/s` 全部来自 DRAM；
4. `32×33` 对所有GPU架构和所有矩阵规模都是最优配置；
5. `4096 × 4096` 带宽下降的唯一原因。

严格验证硬件事件需要 profiler 查看 shared-load bank conflict、shared
transactions、DRAM throughput 等指标。

## 12. 实验总结

本次实验形成了完整的三层对照：

```text
Naive
全局读合并、全局写不合并
≈ 164 GB/s

        ↓ shared-memory tile

Tiled
全局读写都合并、shared读取有bank conflict
≈ 319 GB/s

        ↓ 每行增加一列padding

Padded
全局读写合并、shared读取避免bank conflict
≈ 460～496 GB/s
```

最大矩阵上的最终结果：

```text
Naive  → Padded：2.81×
Tiled  → Padded：1.44×
有效带宽：459.93 GB/s
正确性：PASS，零误差
```

## 13. 一句话总结

> Padding 没有改变矩阵算法，只用每个 block 额外128 Byte shared memory
> 改变了行跨度，使一个 warp 的列读取从“争抢同一个 bank”变为“分散访问
> 32个 bank”；实验中由此获得了相对 tiled `1.44～2.07×` 的大矩阵加速，
> 证明数据布局本身就是重要的性能优化工具。
